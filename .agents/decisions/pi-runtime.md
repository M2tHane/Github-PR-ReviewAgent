# Pi Runtime

## Context

Agent 最初用 Pi SDK 在服务进程内运行，读写、搜索等基础工具都由服务自己实现。开发任务需要像编码助手一样边读边改、运行检查，还要用上 Pi 的插件（codegraph）、AGENTS.md 和 Skills；继续自写工具成本高，也用不上这些生态。

## Decision

所有 Agent（Review、Reply、Decision Extractor、Health、开发任务）都由 [Pi 运行器](../../src/pi/session.ts) 启动独立的 `pi` 进程（RPC 模式），一个任务一个进程，结束时连同它启动的命令（同一进程组）一起结束。

- **资源只来自服务。** 关闭 Pi 的扩展、Skills、提示模板、主题和上下文文件自动发现；只加载服务的 [AGENTS.md 与 Skills](../../agent/)、[服务扩展](../../src/pi/extension.ts) 和服务自己的 [codegraph 扩展](../../src/pi/codegraph-extension.ts)。Pi 配置目录每次新建，不读宿主机 `~/.pi` 和仓库 `.pi`。仓库 AGENTS.md 由服务从目标分支读出后附在系统提示末尾，作为参考。
- **规则优先级：** 服务的安全要求与输出格式 > 团队规则（例外优先于原规则）> 仓库 AGENTS.md。仓库的 CLAUDE.md、`.claude/rules` 不加载。
- **工具：** 使用 Pi 内置的 read、grep、find、ls、bash；只有开发任务另有 edit、write。Health 只用服务端工具，按读过的行核对证据。
- **服务扩展只转发：** 文件工具的路径限制在工作区内，读取结果打码；写入前问服务（保护范围、覆盖前先读），读写后由服务附加匹配的团队规则；服务端工具在服务进程里执行。状态都留在服务里。
- **预算由本地模型代理执行：** Pi 只拿到占位 key 和代理地址。代理在每次请求前持久化预留额、收紧输出上限，超预算直接拒绝，不转发；转发时换成真实 key。
- **开发改动从工作区收集：** 和运行前记录的快照逐个比较（Agent 自己 commit 也算），按 .gitignore 过滤未跟踪文件，再查路径、保护范围、文件数和大小。
- 工作区没有 `.codegraph/` 时先建索引，不缓存；建索引失败不影响任务，只是不加载 codegraph 工具。每个 Pi 进程只启动一个常驻 codegraph（关闭共享守护进程），启动时预热；查询固定在当前工作区。
- **执行过程按 Pi 会话保存：** Pi 把会话写在临时运行目录；运行中每 5 秒（有变化时）和结束（含失败、超时、取消）后由[服务整理](../../src/pi/session-record.ts)存入 `agent_sessions`，管理页按步骤展示，也可下载。各步耗时由服务从 RPC 事件流记下，会话文件只有每条记录的写入时刻，算不出并行工具各自的耗时。

## Why

codegraph 每个新进程的第一次查询要先加载索引（实测约 6 秒），第三方插件每次查询都新起进程，还会留下脱离进程组、空转 5 分钟的守护进程，所以 codegraph 工具由服务自己实现。Pi 的 `before_provider_request` 钩子抛错不会阻止请求，预算只能在进程外拦截，所以用本地代理。凭据不出现在 Pi 的配置、命令行和环境变量里。只看 token 和总耗时查不出 Agent 把时间花在哪、做过什么，所以保存每一步；模型思考过程不保存，只留它说出来的话、工具调用和结果。bash 让 Agent 能运行检查，代价是它和服务同一系统用户：环境变量和 HOME 隔离只能避免顺手暴露，挡不住刻意读取，需要更强隔离时再改为每任务一个容器。

## Constraints

- 新增 Agent 调用一律走 `runPiSession`（经 `runAgentSession`），不要直接启动 Pi 或调用 SDK 的 `createAgentSession`。
- Pi 子进程只拿 `processEnv()` 给的变量，不继承数据库、GitHub、企微和模型凭据；新增变量要逐个评估。
- 关闭 Pi 自身的重试和上下文压缩：重试由任务队列按错误类型决定，压缩会让预算和证据难以核对。
- 写入检查只是第一道关：命令也能改文件，开发任务发布前必须对收集到的全部改动再查一遍。
- 会话记录保存前必须去掉思考过程和图片数据、截断（单段 2 万字符、整份 10 MB）并打码；它含源码片段和任务原文，只给有该仓库权限的维护者看，随任务按保留期删除。保存失败只记日志，不影响任务。
- 升级 Pi 或 codegraph 要跑 `test/pi/session.test.ts`：RPC 事件、扩展钩子和 CLI 参数都和版本绑定。
