# WeCom Development Tasks

## Context

用户新增群内图文开发能力，需要管理员例外、开发者文件保护和自动提 PR。原 Review／Reply／Health Agent 的只读边界不能直接扩大，群内文字也不能成为身份授权。

## Decision

群与仓库、目标分支绑定；管理页维护企微 ID 的角色及保护范围。开发任务使用独立持久表和 Worker，从固定目标分支 SHA 读取代码与 ACTIVE 规则，模型只提出完整文件改动，服务验证后用 installation token 创建新分支与 PR。权限、路径和保护范围由确定性代码强制检查。

管理员发起任务可修改保护范围，规则本身继续有效；开发命中后整项拒绝。服务先保存预期分支与 head，再开始远端发布，PR 归属记录用于跳过自动审查。群消息和发布结果持久去重；不确定结果只核对，不盲目重发。

## Why

模型角色提示不能构成权限边界。受控文件提案与 Git Data API 避免在服务宿主机执行目标仓库代码、Git hooks 或模型 shell。发布前保存归属可处理 GitHub Webhook 比创建响应更早到达的竞态，避免自我审查循环。

## Constraints

- Review／Reply／Health 保持只读；开发也不执行目标仓库安装、构建、测试及自动合并。
- 成员身份只取可信企微回调，设置写入需要 GitHub 维护权限和 CSRF。
- 保护集不经过检索裁剪；写入前重新检查设置版本、权限与目标分支。
- 同 Bot 只有一个持有数据库会话锁的开发 Worker；丢失执行权后不得更新任务。
- PR 来源不能仅靠可编辑标题、正文或标签；开发 PR 归属随仓库生命周期保留。
- 凭据不进入 Prompt、代码、日志或管理页；运行结果与用量不冒充仓库测试验收。
