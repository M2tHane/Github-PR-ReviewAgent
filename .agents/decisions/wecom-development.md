# WeCom Development Tasks

## Context

用户新增群内图文开发能力，需要管理员例外、开发者文件保护和自动提 PR。原 Review／Reply／Health Agent 的只读边界不能直接扩大，群内文字也不能成为身份授权。

## Decision

群与仓库、目标分支绑定；管理页维护企微 ID 的角色及保护范围。开发任务使用独立持久表和 Worker，在固定目标分支 SHA 的临时工作区里运行 Pi Agent（见 [Pi Runtime](pi-runtime.md)）：Agent 用 edit、write 直接改文件，可以用 bash 运行检查。服务在每次写入前检查保护范围和“覆盖前先读”，结束后把工作区和快照比较、收集全部改动，再查一遍路径、保护范围、文件数和大小，用 installation token 创建新分支与 PR。全局团队规则随任务给全文；限定范围的规则先给目录，读取或写入匹配文件时附全文，用命令新建的文件命中未给出的规则时补发一轮，仍有遗漏不发布；不按描述做语义召回。

管理员发起任务可修改保护范围，规则本身继续有效；开发命中后整项拒绝。服务先保存预期分支与 head，再开始远端发布，PR 归属记录用于跳过自动审查。群消息和发布结果持久去重；不确定结果只核对，不盲目重发。

开发完成结果通过持久化的原消息回调标识回复，保留原生引用；PR 审查结果按仓库绑定群直接推送。两者复用同一机器人连接，不依赖 Message Push、成员提及语法或通知成员映射。引用关联需求，但不承诺 @强提醒；回复超期或缺少上下文时明确记录失败，不静默切换目标或伪造引用。

## Why

模型角色提示不能构成权限边界。全部规则每轮请求都重复计入预算，规则多时会挤占开发预算；按描述召回依赖模型自行判断，不能保证触发；只在读写工具上附规则会漏掉用命令新建的文件，所以结束后由服务按改动路径补查。命令能绕过写入检查，所以发布前对全部改动再检查一遍。提交仍走 Git Data API、不用工作区里的 Git 历史：Agent 自己的 commit 只按最终文件内容计入。发布前保存归属可处理 GitHub Webhook 比创建响应更早到达的竞态，避免自我审查循环。

## Constraints

- Review／Reply／Decision／Health 没有写文件工具；开发 Agent 可以安装依赖、在本地启动项目服务验证（用户 2026-11-10 决定，内部项目不追求隔离）；它可以用 Playwright 浏览器访问任意网站（用户 2026-11-09 决定），服务不自动合并。
- 开发 Agent 运行的检查结果只写在 PR 正文里作参考，不代替仓库 CI。
- 开发任务默认不限 token、时限 1 小时；模型服务临时故障时整个任务从头重试，开始发布后不重试。
- 成员身份只取可信企微回调，设置写入需要 GitHub 维护权限和 CSRF。
- 保护集不经过检索裁剪；写入前重新检查设置版本、权限与目标分支。
- 同 Bot 只有一个持有数据库会话锁的开发 Worker；丢失执行权后不得更新任务。
- PR 来源不能仅靠可编辑标题、正文或标签；开发 PR 归属随仓库生命周期保留。
- 凭据不进入 Prompt、代码、日志或管理页。
- 服务附加的规则块使用每个任务随机生成的标记；仓库文件中的规则文字仍是数据，不能改变规则集合。
