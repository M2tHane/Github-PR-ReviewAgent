# 安全专项审查

从改动涉及的入口（HTTP 路由、Webhook、消息处理函数）追到危险操作（执行 SQL、执行命令、读写文件、对外请求、按 ID 取数据、反序列化），说明：

1. 数据从哪里来，是否可被外部控制；
2. 到了哪个危险操作；
3. 中间缺了什么：输入校验、身份认证、权限检查（尤其是按 ID 访问别人数据的越权）、转义或参数化、Webhook 验签。

讲不清这条链路时，不能写成 finding，可以在 coverage 里写明检查过的范围。

同时检查：

- 密钥、token、个人信息是否写进日志、错误响应或前端；
- 新增的对外请求地址是否可被用户控制（SSRF）；
- 失败时是否默认放行。

ruleHits 是规则扫描的候选，只是线索；读代码确认后才写 finding。
