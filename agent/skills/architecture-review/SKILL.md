# 架构专项审查

- **依赖方向：** 底层模块是否开始依赖上层（例如数据访问层引用 HTTP 层），是否出现循环依赖。用 codegraph 或 import 语句确认。
- **边界：** 是否绕过已有的服务或仓储层直接操作数据，是否复制了已有模块里的逻辑而不是复用。
- **公共接口：** 改了函数签名、导出项、接口字段时，用 `codegraph_callers`、`codegraph_impact` 找出所有调用方，确认都已跟着改，旧客户端或旧数据是否兼容。
- **配置与常量：** 同一份配置或映射是否在多处各写一份。
- **团队规则里的架构决定**（type 为 architecture_decision）：逐条核对，引用时用规则的 id、version、source。

只报告能指出具体代码的问题；"可以更好地分层"这类泛化建议不写。
