# 提交与 PR 规范

## 标题

```
<类型>(<范围>): <简体中文描述>
```

范围不明确可省略，例如 `fix: 修复使用日志导出币种`。

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(topup): 支持对公收款补传水单` |
| `fix` | 缺陷修复 | `fix(logs): 修复导出时币种丢失` |
| `refactor` | 重构，行为不变 | `refactor(billing): 抽取任务结算统计调整函数` |
| `perf` | 性能 | `perf(logs): 导出改为按主键分批迭代` |
| `docs` | 文档 | `docs: 补充生产配置注意事项` |
| `test` | 测试 | `test(model): 增加启动检查回归测试` |
| `chore` | 构建、脚本、依赖 | `chore: 更新部署脚本` |

## 正文

简短，按顺序写：

1. **主体：** 一两句话说清解决了什么问题、新增了什么行为，以及关键做法。
2. **同时优化 / 同时实现：** 有次要改动时空一行写这个小标题，再用列表逐条列出（日志、顺带修复、配置、测试等）。没有就不写，不凑条数。
3. **影响说明：** 是否改了数据库结构、是否需要迁移，是否改了部署配置、依赖或兼容边界。没有数据库变更时写"无需数据库结构变更或迁移"。
4. **验证：** 一句话写实际运行过的检查和结果；没运行就写"未运行构建或测试"。

不写：读文件的过程、内部执行状态、大段测试日志、AI 生成脚注（如 `Co-Authored-By`、`Generated with`）。

示例：

```
修复视频再生成时，同渠道、同 API Key 仍错误进入转存流程的问题。补全原任务凭据读取，并保存 Key 校验指纹。

同时优化：

- 增加转存原因和上传失败日志，敏感信息已脱敏。
- 添加相关回归测试。

无需数据库结构变更或迁移，不修改部署配置。已运行 go test ./service/video/...，通过。
```
