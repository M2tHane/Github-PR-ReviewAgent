# 团队规则导入

在管理页的「团队规则」中选择「导入 Markdown」或「从其他项目导入」。导入规则属于所选目标项目，确认后立即成为生效规则，供后续 PR 审查和开发任务读取。是否在某次审查中引用，仍由原有范围过滤和召回逻辑决定。

## Markdown 流程

1. 打开导入页面，先查看或复制格式示例。
2. 按示例整理 `.md` 文件，选择目标项目并上传。
3. 点击「校验并预览」，核对规则正文、制定原因、范围、来源和重复提示。
4. 勾选需要的规则，点击「确认导入并生效」。预览本身不创建规则。

示例：

```markdown
# 团队规则

## TEAM-001｜金额使用最小货币单位

类型：工程规范
适用路径：`service/billing/**`、`model/payment/**`

### 规则内容
金额使用整数形式的最小货币单位，避免浮点误差。

### 制定原因
保证计费和退款计算一致。

### 适用条件与例外
涉及扣款和退款时适用。展示层可以将整数转换为格式化金额。

### 参考依据
填写团队规范、历史提交链接或其他可核对的依据。
```

格式约定：

- 文档以 `# 团队规则` 开始；每条规则使用 `## 编号｜名称`。编号由字母、数字、下划线和连字符组成，最多 64 字符，在同一文档内唯一；编号不是数据库规则 ID。
- 类型、适用路径、规则内容、制定原因必填。名称最多 200 字符。
- 类型支持架构决策、工程规范、安全规则、编码约定、例外规则、废弃模式。
- 路径以反引号包裹，以顿号分隔；全局规则必须明确填写 `适用路径：整个仓库`。路径为仓库内相对路径或 glob，最多 50 项，每项最多 300 字符。
- 「适用条件与例外」「参考依据」是可选栏目，保留在规则正文中；叙述性的适用条件不会自动转换成机器过滤条件。
- 正文可包含配对的反引号或波浪线代码围栏。文档标题、规则标题和栏目标题使用示例中的层级；未知字段、重复栏目、缺字段会报错并显示行号，不能靠模型猜测格式。
- 例外规则需额外填写 `例外关联：TEAM-001`，指向同一文档中的原规则，并明确限定路径。预览时必须包含原规则；确认时需勾选原规则，或目标项目已有内容一致且生效的原规则副本。关联在目标项目内重建。
- 每次最多 100 条，Markdown 文件最大 512 KiB。预览有效期为 30 分钟。

现有 [tuzi-api 的 50 条候选规则](team-rules/tuzi-api.md) 和 [证据文档](team-rules/tuzi-api-evidence.md) 仍保留原格式与内容。它们不是自动导入文件，也没有因功能上线而自动生效。需要按此格式整理，并由维护者选定目标项目后确认。

## 从其他项目选择规则

选择有维护权限的来源项目，搜索并勾选生效规则，可逐条调整目标项目路径，然后预览确认。来源项目正在编辑但尚未确认的版本不参与复制，当前生效版本仍可选择。

副本获得目标项目的新规则 ID，记录来源项目、原规则 ID 和版本，保留正文、依据、不确定因素及其他范围维度。副本独立维护，不自动同步，也不会复制原规则的停用或替代状态。

预览与确认都会重新校验权限；确认前来源版本被修改、停用或失去访问权限，必须重新处理。无权查看的项目不能作为来源。确认失败时整批回滚，不会只生效一部分。

## 重复、冲突与审计

完全相同以类型、标题、正文、制定原因、规范化后的范围和目标项目内的例外关联判断；来源与证据来源不同不会单独产生新副本。相同内容存在于目标项目的任何历史状态时跳过，不覆盖、不自动激活旧规则。同一批中的重复项也只创建一份。

同名但内容或范围不同会提示，确认后创建独立规则。系统不判断语义冲突，也不自动替代原规则。若确认前目标项目新增同名冲突，会要求重新预览。

导入记录保存文件名和 SHA-256 摘要或原项目规则版本，以及确认人和时间。人工导入没有模型置信分数。以后编辑仍沿用「生成待确认新版本 → 确认后生效」流程；PR 自动提取的来源校验与人工审批不变。

确认在数据库事务中写入规则和审计。同一预览的重复点击返回同一结果；不同预览并发导入同一内容也不产生重复规则。预览与操作人、目标项目绑定，到期预览在下一次创建预览时清理。

## 安装与运行

新增增量迁移 [006_rule_import.sql](../migrations/006_rule_import.sql)，用于导入预览和人工确认记录。部署时按现有流程构建、执行迁移并重启服务；只刷新前端不足以启用新接口。不要直接对旧数据库执行 baseline。

导入不调用模型、不操作 GitHub 仓库文件或 PR。运行开销集中在导入请求：跨项目操作增加来源权限检查；预览读取来源规则和目标项目历史，确认按批次加锁，每新增一条规则写入规则及审计各一次。已有审查的查询方式不变，但导入更多生效规则会增加候选集合；开发任务现有实现会读取项目全部生效规则。没有新增定时器或常驻后台任务。验证记录与性能边界见 [任务清单](tasks/RULE-IMPORT.md)。
