## 使用方式

评审一项变更时，先匹配下面的路径，再核对正文中的业务条件；路径命中只是阅读线索，不意味着违规。沿调用链检查完整实现，不能只看 diff 中有没有某个函数名。每个问题需要给出触发输入、实际后果、变更位置和证据。

每条规则的正文、例外、触发条件作为一个整体使用。不要只抽出一句“必须”导入，也不要将例外拆成没有原规则关联的另一条强制规则。同一根因只提出一个问题，可关联多个规则；不根据源文档中的 P0/P1 机械决定 finding 严重程度。

发现新的决定与本文矛盾时，核实适用范围及替代依据；证据不足则暂停该条规则的确定性判断，列出冲突供维护者决定。不能因为代码更新较晚，就推断团队已经废弃原规定。

## TUZI-001

**生产只支持 MySQL，不再要求新增三库兼容实现。**

- **适用条件**：变更生产数据库查询、schema、迁移、数据库测试或 CI。
- **规则**：以 MySQL ≥ 5.7.8 为生产目标，迁移考虑 MySQL 5.7／8；优先 GORM，允许 MySQL 专用 SQL。新增专用 SQL 必须有对应 MySQL 集成用例，schema／迁移／原始 SQL 的交付说明应明确 MySQL 是否实测。
- **边界**：内存 SQLite 单元测试继续保留；现存 SQLite／PostgreSQL 分支不因本规则被要求清除，也不要求为新功能扩充这些分支。缺少测试 DSN 而 skip，不能写成 MySQL 验证通过。
- **应提示的例子**：新增 `ON DUPLICATE KEY` 计费路径却只有 SQLite 测试，并声称已验证该 SQL。
- **不应提示**：仅因使用 MySQL 专用语法而要求增加 PostgreSQL 等价实现；仅因出现 SQLite 测试就认为违背生产规范。
- **依据**：[E01](tuzi-api-evidence.md#e01)。新规则明确替代历史“三库都必须支持”的要求。

## TUZI-002

**普通启动只校验结构，DDL 走明确的迁移入口。**

- **适用条件**：新增或修改表、列、索引，或者调整应用启动路径。
- **规则**：普通 API、relay-only、非 master 启动不能偷偷执行 DDL；必需结构缺失时应明确提示迁移。新结构与只读校验同步维护，迁移需可重复执行。受保护热表和受控表的大型变更进入现有迁移计划流程。
- **边界**：显式迁移入口本来就允许 DDL；旧辅助函数或测试中存在迁移代码，不等于普通启动会执行。表分类以当前 `protectedMigrationTables`／`controlledMigrationTables` 为准，不能从本文复制一份永久不变的清单。
- **应提示的例子**：新增功能在普通启动时自动给 `logs` 补索引，或新增必需列却既无迁移计划也无缺失检查。
- **不应提示**：只读元数据查询；`/db-migrate` 中受现有计划和锁约束的建表操作。
- **依据**：[E02](tuzi-api-evidence.md#e02)。判断实际调用链，不把规范中的概念签名 `InitDB(runMigrate=true)` 当成真实函数签名。

## TUZI-003

**同一事务使用同一连接，跨库投递不伪装成共同事务。**

- **适用条件**：同一业务动作有多个必须原子完成的数据库写入，或涉及主库与日志库。
- **规则**：业务逻辑复用回调式事务；回调内属于该事务的查询和写入使用传入的 `tx`，嵌套 helper 也传递该连接。HTTP、Redis、通知不放进可重试事务回调。最终消费日志 `logs` 使用 `LOG_DB`；主库事实和可恢复投递记录先在主库提交，再按现有机制交付日志。
- **边界**：`RequestBillingLog` 虽然名称带 Log，实际是主库的待投递计费记录，必须与资金变更一起提交，不能挪到 `LOG_DB`。不能要求两库必然同库或放进一个事务。已提交资金不能因日志投递失败直接回滚或重复扣款。
- **应提示的例子**：事务中的 helper 通过全局 `DB` 修改余额；日志投递失败后重新执行扣款。
- **不应提示**：成功提交后刷新缓存；主库待投递记录与最终日志异步同步；仅因包装层内部实现事务管理而机械报“手工事务”。
- **依据**：[E03](tuzi-api-evidence.md#e03)。与 TUZI-004 一起使用：可恢复异步投递不等于丢失资金事实。

## TUZI-004

**资金副作用由持久化事实约束，不把未知提交当成确定失败。**

- **适用条件**：余额、quota、预扣、结算、退款、回调、计费补偿或相关重试发生变化。
- **规则**：复用对应资金路径的原子更新、唯一事件或版本条件，保证重复请求／回调／多节点执行不会重复生效；更新该路径实际涉及的余额、消耗统计及可恢复日志。事务提交结果未知时先保留不确定状态和核对依据，不能直接按“未发生”退款或再次扣款。
- **边界**：不是每个资金路径都使用 `request_billing_records`，不能为了统一表名重写其他已验证机制。没有持久化重放保护的路径不得重试未知 COMMIT；有保护的路径仍只能按既有重试分类处理。只读展示统计的时效要求不等于资金事实原子性。
- **应提示的例子**：网络断开后立即退还可能已结算的预扣；仅用进程锁保护跨节点退款；幂等键相同却允许不同金额再次执行。
- **不应提示**：确认回滚后的有限死锁重试；数据库保幂等前提下的本地调度锁。检查 `RowsAffected` 时不能认定 0 永远意味着失败：同秒续租可由当前锁定读核验 owner、token 和实际到期值。
- **依据**：[E04](tuzi-api-evidence.md#e04)。视频交接统计曾恢复同步；这只约束相应路径，不能推导出“所有日志必须同步”。

## TUZI-005

**结算保留冻结价格与用量来源，缺失值不冒充明确的零。**

- **适用条件**：动态计费、异步图片／视频任务预扣和结算、usage 解析或计费上下文持久化。
- **规则**：使用提交／预扣时冻结的计费快照与可确认用量结算，不改用任务完成时的最新价格。区分字段不存在、解析失败、明确为 0 和有依据的估算；无法确认用量时沿用该路径已有的保守处理及待核查标记，不能直接按零结算。
- **边界**：明确返回的 0 是合法事实，不应改成预扣值。MiniMax-H3 的有限例外：缺输入图片数时可使用提交时已验证、冻结且有存在标记的数量（包括 0）；缺参考视频输入秒数时，按已有合同使用输出时长并标注来源；缺输出时长仍待核查。旧任务没有存在标记不能推断为 0。该例外不能扩展为所有供应商都可使用请求时长代替实际用量。
- **应提示的例子**：任务缺失图片 usage 时无条件写 `0`；结算重读现价；只在内存保留零值存在标记、落库重放后丢失。
- **不应提示**：有明确来源的 H3 零图片快照；上游显式返回零并覆盖估算；不同账务阶段的合理保守策略。
- **依据**：[E05](tuzi-api-evidence.md#e05)。建议回归覆盖“缺失／明确零／非零／历史快照缺标记／序列化后重放”。

## TUZI-006

**普通用户 API 令牌命中缓存后仍核验当前访问策略。**

- **适用条件**：`TokenAuth`／`TokenAuthReadOnly` 对普通用户 Token 的认证链路、缓存或 IP 规则发生变化。
- **规则**：缓存命中不能单独证明令牌仍有效。保留数据库对缓存身份和当前 key 的绑定核验，以及状态、过期时间、允许／排除 IP 的新鲜读取，遵守软删除过滤。数据库核验失败不得退回旧缓存授权；请求取消应传入查询。
- **边界**：Redis 失败可以回源数据库；已完成权威核验后的缓存回填失败不应改变认证结果。本文不要求所有请求数据禁用缓存，也不把此查询结构套到 MCP OAuth、系统令牌等不同身份模型。
- **应提示的例子**：命中 Redis 即提前返回允许，导致刚撤销的令牌或新 IP 限制失效；数据库错误时沿用缓存中的放行结论。
- **不应提示**：缓存存储非权威数据、同时查询当前策略；缓存故障后数据库验证成功。
- **依据**：[E06](tuzi-api-evidence.md#e06)。这里的“拒绝放行”与非安全关键缓存的可用性降级不冲突。

## TUZI-007

**凭据保护覆盖日志、错误、列表和带认证的外发请求。**

- **适用条件**：新增诊断内容、公开错误、渠道信息返回、上游请求／重定向，或处理自定义认证字段。
- **规则**：密钥、令牌及完整敏感正文不进入普通日志、公开错误或普通列表。诊断保留长度、摘要、请求标识等必要元数据；不能重新输出 JSON 首尾原文片段。带凭据请求保留当前 credential policy，对目标来源、自定义 header／query 和重定向统一约束。
- **边界**：识别凭据不能只检查字段名为 `Authorization` 或字符串以 `sk-` 开头。经专门权限控制的凭据创建／读取流程需要单独核对权限和脱敏合同，不能与普通列表混为一谈。正常向配置允许的供应商发送认证凭据是必要行为；允许的来源也不等于可以访问任意用户 URL。
- **应提示的例子**：JSON 解析失败打印前后 1 KB；跨来源重定向继续携带自定义认证 header；渠道列表泄露完整密钥。
- **不应提示**：仅记录 token ID、长度、摘要或固定原因码；经过既有策略检查的上游认证请求。
- **依据**：[E07](tuzi-api-evidence.md#e07)。旧诊断提交已被安全修复替代，不能以“历史就是这么做的”恢复。

## TUZI-008

**MCP 私有数据加入用户删除清单，并防止删除后的迟到写入。**

- **适用条件**：MCP 授权、动作、按用户限流记录，以及 MCP 动作最终创建 API Token 的路径。
- **候选规则**：新增这类用户私有数据时，纳入统一备份／删除／恢复清单，使用正确归属条件。可能与硬删除竞态的创建步骤，在短事务内遵守当前 user → OAuth family → action／counter 的锁顺序；最终 Token 插入也要核验用户仍存在且有效。
- **边界**：仅删除表中旧记录不足以阻止此前已鉴权请求重建数据；也不能为了防竞态在整个 HTTP 调用期间持用户锁。保留的管理员审计记录不是应随用户清除的私有凭据。数字用户 ID 前缀匹配必须包含分隔符，用户 1 不能匹配到用户 10。
- **应提示的例子**：新增 MCP 私有表遗漏删除注册；动作领取后发生用户删除，最终插入 Token 时不再核验。
- **不应提示**：按统一设计保留的管理审计；没有持锁跨 HTTP 的短事务；普通网站 Token 路径仅因未使用 MCP helper 被判违规。
- **依据**：[E08](tuzi-api-evidence.md#e08)。这是局部修复的可复用提炼，不宣称所有业务都必须采用同一用户锁。

## TUZI-009

**可选请求标量区分未传和显式零值。**

- **适用条件**：客户端 JSON 解析后又编码转发上游的请求 DTO 和协议转换。
- **规则**：可选标量使用 `*T` 配合 `omitempty` 保留存在性：未传为 nil 并省略，传 `0`／`false` 则仍发送。转换链路不得在解引用、默认赋值或中间结构体中丢失该语义。
- **边界**：不要求所有 Go 字段都改指针；必填字段、内部计算值、响应结构及明确与缺失等价的字段需按各自合同判断。保留字段不代表允许无效取值通过业务校验。
- **应提示的例子**：新增可选 `seed int` 配 `omitempty`，使用户指定 `seed: 0` 转发时消失；`include_usage: false` 被默认逻辑覆盖。
- **不应提示**：仅用 `json.RawMessage` 保留未知字段；必填内部计数使用整数；校验层按协议拒绝非法零值。
- **依据**：[E09](tuzi-api-evidence.md#e09)。TUZI-005 管结算事实，本文管请求存在性，两者都不能简化成“零值一律丢弃／一律收费”。

## TUZI-010

**业务 JSON 编解码使用公共封装，类型引用与局部字段读取另行判断。**

- **适用条件**：业务代码新增 JSON 序列化／反序列化操作。
- **规则**：实际 marshal／unmarshal／decode 复用 `common/json.go` 提供的公共方法，避免绕过统一处理。
- **边界**：公共封装内部可以使用 `encoding/json`；业务结构中引用 `json.RawMessage`／`json.Number` 等类型不违规。现有为流式检查或减少媒体复制而使用的 `gjson` 局部读取，不等同于直接调用 `encoding/json.Unmarshal`，不能仅凭包名要求重写成全量解码。是否保留正确解析语义仍需检查。
- **应提示的例子**：新增业务 handler 直接调用 `json.Unmarshal`，绕过现有公共封装。
- **不应提示**：DTO 引用 `json.RawMessage`；`common.Marshal` 的内部实现；TUZI-012 中保持语义的字段投影。
- **依据**：[E10](tuzi-api-evidence.md#e10)。不得把“统一封装”扩成“必须把完整大正文解码到 map”。

## TUZI-011

**边缘退款扫描需要跨轮推进，不能让前排待确认任务长期占满预算。**

- **适用条件**：`AutoSettleEdgeReviews` 及其调度、分页、取消处理。
- **候选规则**：保留单轮页数／批量上限和跨轮进度；任务暂不可结算不能使后续任务永久不可达。扫描结束后循环，错误／取消时不得把尚未处理的记录越过；实际结算继续依赖数据库版本和状态检查。
- **边界**：常量大小的进程内游标和防重入锁可以用于扫描调度，重启只重扫，不承担资金幂等。不能据此禁止 `sync.Mutex`，也不能把游标当作已结算凭证。不能强制所有队列都改成相同方向、相同页大小。
- **应提示的例子**：每轮从头读固定数量的待确认任务，前排长期无法完成，使后面的可退款记录始终读不到。
- **不应提示**：本地游标辅助遍历，数据库条件控制资金副作用；取消后保留未完成位置。
- **依据**：[E11](tuzi-api-evidence.md#e11)。由近期具体修复提炼，扩展到其他扫描器前需再查对应队列合同。

## TUZI-012

**Seedream 图片计费复用不可变请求体，优化不能改变计数与转发语义。**

- **适用条件**：Seedream 请求重放、计费字段提取、图片引用计数。
- **候选规则**：避免只为计费把同一大图片／base64 请求反复全量解码和复制；在生命周期安全时复用不可变正文，提取必要控制字段，保留表达式计费可读取的原始请求。修改解析方式需保持重复键、嵌套图片及不同引用形态的现有语义。
- **边界**：允许必要的有界复制，也不要求整个项目做到零拷贝。借用正文不得越过其生命周期或修改原缓冲区。计费侧的嵌套引用计数与最终请求 DTO 的单对象引用识别并不完全相同，不能为去重代码而强行合并。
- **应提示的例子**：新增一次完整媒体 DTO 解码只为取得模型名；优化时丢掉原始字段，导致表达式或实际转发改变。
- **不应提示**：正常协议转换所需的复制；有依据的轻量字段读取；两套确有不同合同的计数逻辑。
- **依据**：[E12](tuzi-api-evidence.md#e12)。性能判断需给出对象大小、复制次数或测量证据，不能仅凭代码行数。

## TUZI-013

**翻译项放入 translation 对象，空译文保留中文回退。**

- **适用条件**：前端翻译资源、i18n 初始化、提取工具或新增用户文案。
- **规则**：沿用中文源字符串 key、`t(...)` 和 locale 文件的顶层 `translation` 对象。未翻译项允许 `""`，运行时通过 `returnEmptyString: false` 与 `zh-CN` 回退，不能显示空白；合并语言文件时保留已有词条和值。
- **边界**：当前 loader 对完全扁平旧资源有兼容分支，但有 `translation` 对象时会优先选它，混写在外面的新词条不会进入该对象。不能把空译文一律报错，也不能把兼容分支解释为新词条可随意放根层。
- **应提示的例子**：文件已有 `translation`，却把新增 key 写到根层；重新开启空字符串渲染；解决合并冲突时丢掉已有翻译。
- **不应提示**：未翻译项保持空字符串且中文回退有效；没有新增文案的样式修改未改 locale。
- **依据**：[E13](tuzi-api-evidence.md#e13)。不把尚未稳定的 UI 排版偏好提炼成全团队规则。

## TUZI-014

**支付按具体网关保存协议、交互和失败分类。**

- **适用条件**：创建订单、单号生成、回调、查单、补单、网关迁移或充值界面。
- **规则**：变更前核实该环境实际线上版本的行为合同，不拿最新 dev 冒充线上基线。区分支付页地址、二维码图片地址、二维码原始内容；生成单号遵守该 provider 的限制及幂等性。确定拒绝与结果未知分开处理；重复回调不得重复入账。
- **边界**：当前易支付 V2 使用 `/mapi.php` form POST 返回的二维码，不能无授权改为对 `/submit.php` 中间页编码；蓝兔有自己的长度约束，不能推广成所有网关统一限制。不得要求不同二维码库产生相同像素，应比较二维码原始内容和交互形式。显式批准的合同调整需对应新基线，不能以旧规则永久禁止。
- **应提示的例子**：支付超时就标确定失败并换单号重建；通用单号超出蓝兔限制；把二维码图片 URL 当原始内容再次编码。
- **不应提示**：按网关规范采用不同生成器；金额精度正确且内容相同的二维码图案变化。
- **依据**：[E14](tuzi-api-evidence.md#e14)。评审要求说明相关自动化及隔离真实订单验证是否完成；不能据规则自行触发下单、生产操作或外部写入。

## TUZI-015

**保留持久项目归属，运行时宣传提示按明确例外处理。**

- **适用条件**：清理文档、许可、署名、包／模块／部署标识，或删除运行时 banner。
- **规则**：保留 new-api／QuantumNous 的持久归属与许可、包身份及文档署名；批量删除文档前核对是否连带删除这些内容。
- **边界**：当前规范明确允许删除、关闭或按环境开关控制仅运行时的宣传消息，前提是不影响许可、版权、包身份、导入路径、部署标识或文档归属。不能把“文件已不常用”当成删除其归属信息的依据，也不能把运行时例外扩大到 README 或许可证。
- **应提示的例子**：清理旧架构文档时连同版本归属与许可说明一并删除；改 Go module 身份以抹去原项目归属。
- **不应提示**：仅移除运行时宣传日志且保留持久归属。
- **依据**：[E15](tuzi-api-evidence.md#e15)。作为该仓库的评审约定，不授予 Agent 拒绝用户指令、写远端或修改权限的能力。

## TUZI-016

**Seedance 素材绑定原渠道与配置身份。**

- **适用条件**：上传、审核、引用 Seedance 素材，或调整素材渠道选择与缓存。
- **规则**：素材保存原上传渠道、分组和配置指纹；审核与生成核验同一身份。引用多个素材时要求原渠道一致；渠道失效、无权限或身份不可验证时拒绝，不能凭 account_scope 相同换渠道。自动审核 URL/data URI 使用本次生成渠道的配置，缓存隔离渠道和凭据指纹。
- **边界**：本条针对有素材身份约束的请求，不禁止普通无素材请求的合法换渠道重试。素材资源访问权限另见 TUZI-038；存储格式升级另见 TUZI-050。
- **应提示的例子**：A 上传的素材在重试时发往 B，即使两渠道 account_scope 相同也可能使用错误凭据。
- **不应提示**：同渠道且指纹一致地复用已审核素材；普通无素材请求按原策略换渠道。
- **核对场景**：A→B→A 路由、混合渠道素材、凭据轮换、原渠道停用时核对实际收到请求的上游。
- **依据**：[E16](tuzi-api-evidence.md#e16)；专项文档及修复。

## TUZI-017

**重试路由重新读取不可变的原始请求。**

- **适用条件**：修改路由条件提取、请求重放或跨渠道重试。
- **规则**：每轮路由条件从保存的原始 body、path、content type 提取。前一适配器改过的模型名、媒体字段或派生结构不得成为下一轮的原始输入。
- **边界**：适配器仍可构造自己的上游 payload；要求隔离原始快照，不要求所有临时对象全局不可变。
- **应提示的例子**：首轮适配器移除参考视频后，第二轮路由误判为纯文本视频请求。
- **不应提示**：每轮重新解析原始 body，再按所选渠道构建新 payload。
- **核对场景**：同一原始请求在两个不同适配器之间重试，路由媒体事实应保持一致。
- **依据**：[E17](tuzi-api-evidence.md#e17)；局部历史推断。

## TUZI-018

**Responses 只在真实输出前做允许的重试。**

- **适用条件**：调整 Responses 流式错误、生命周期帧缓冲或渠道重试。
- **规则**：先识别无生成内容的 created/in_progress 帧并有界暂存；只有尚未提交实际输出、仍符合本地控制输出判据且错误属于可重试类别时，才允许换渠道。生成内容一旦发出，不能重放整次生成；明确参数或内容审核错误不靠重试掩盖。
- **边界**：当前上限为 8 帧／64 KiB；更改上限需证明仍有界，不把数字当作永恒规范。不能单看 Writer.Written：本地控制帧与生成输出不同。HTTP 200 终止兼容见 TUZI-019。
- **应提示的例子**：把 response.created 立即写给客户端，导致随后可重试的限流错误无法正常换渠道；或发出正文后再重试导致重复输出。
- **不应提示**：仅有本地控制输出且上游返回可重试错误时丢弃私有生命周期帧后重试。
- **核对场景**：分别覆盖生命周期帧后 429、正文后 429、内容审核错误、缓冲超限。
- **依据**：[E18](tuzi-api-evidence.md#e18)；局部历史推断。

## TUZI-019

**HTTP 200 文本流沿用明确的终止兼容合同。**

- **适用条件**：修改已接入 HTTP200StreamCompletionRecovery 的文本流完成逻辑。
- **规则**：对符合该恢复路径的 HTTP 200 文本流，空正文、缺终止帧或读取中断可按正常完成处理，同时保留内部终止恢复原因和读取诊断。provider error、非法 payload、转换失败等必须先记录并优先处理，不能被 200 恢复覆盖。
- **边界**：非 200、客户端断开以及图片／音频／任务流不由本条一概认定成功。HTTP 200 本身不是全系统成功判据；与 TUZI-022 一起核对。
- **应提示的例子**：为所有文本流新增“缺 [DONE] 一律 502”，重新破坏现有兼容合同；或把 provider error 清空后按 200 成功。
- **不应提示**：符合恢复条件的文本流缺终止标记但保留诊断并正常收尾；媒体流按自身合同报错。
- **核对场景**：200 空体／提前 EOF、明确 provider error、非法 JSON、非 200、客户端断开各走对应路径。
- **依据**：[E19](tuzi-api-evidence.md#e19)；专项设计及替代历史。

## TUZI-020

**上游模型别名在具体适配器边界归一化。**

- **适用条件**：修改 Seedance V3 的模型映射或 Doubao 请求构建。
- **规则**：在 Doubao 最终上游 payload 中把支持的旧 PixMax 模型枚举转换为 Doubao 规范名。构造独立 payload，保留原请求、公开模型与计费／日志字段各自的含义。
- **边界**：只处理已知映射，不用宽泛子串匹配修改任意第三方模型；不要求其他 provider 使用 Doubao 名称。
- **应提示的例子**：公开 Seedance 别名经过 model_mapping 后仍以 PixMax 枚举发往 Doubao V3。
- **不应提示**：客户端与任务保留公开名，只有 Doubao wire payload 使用 canonical model。
- **核对场景**：旧别名、已规范名、无关模型以及重试时原请求未变。
- **依据**：[E20](tuzi-api-evidence.md#e20)；局部历史推断。

## TUZI-021

**任务适配器选择贯穿提交、轮询与查询。**

- **适用条件**：新增异步任务平台，或修改 task_adaptor 和平台推断。
- **规则**：同时检查提交、后台轮询和查询响应转换的有效适配器，保证同一任务按一致协议处理。task_adaptor 为空时仍按渠道类型推断；状态映射保留未知状态，不能因此直接退款或结算。
- **边界**：Suno 有显式协议与请求方言的优先级；不能用通用 task_adaptor 规则覆盖这些分支。本条不要求每条路径都调用同一个函数。
- **应提示的例子**：提交支持新 task_adaptor，轮询仍用旧平台解析并把未知状态当失败退款。
- **不应提示**：未设置覆盖项的老渠道按类型推断；Suno 显式 native 协议继续走专用优先级。
- **核对场景**：有／无覆盖项分别走提交→轮询→用户查询，并加入未知上游状态。
- **依据**：[E21](tuzi-api-evidence.md#e21)；明确规范及当前实现。

## TUZI-022

**上游 HTTP 状态与实际完成结果分别记录。**

- **适用条件**：修改多次上游尝试的记录、成功统计或异步诊断快照。
- **规则**：按 channel_id 与 retry_index 标识尝试，保留原 HTTP 状态，单独记录 completed_success。解析／协议错误不能仅凭 200 标成成功；后续结果更新不原地污染已交给异步日志的切片。
- **边界**：本地预检拒绝不虚构上游尝试。符合 TUZI-019 的文本流恢复可按完成合同成功，同时保留截断诊断；不要求把该兼容成功重新记成失败。
- **应提示的例子**：上游 200 返回错误体，统计仍只按状态码计成功；异步日志看到被下一轮覆盖的尝试结果。
- **不应提示**：HTTP status=200 而 completed_success=false；合法兼容收尾为 true 且保留恢复原因。
- **核对场景**：同渠道两次重试、200 错误体和异步读旧快照。
- **依据**：[E22](tuzi-api-evidence.md#e22)；局部历史推断。

## TUZI-023

**命中的用户模型折扣替代整个分组倍率。**

- **适用条件**：修改用户模型折扣、分组倍率或普通／异步任务的有效倍率计算。
- **规则**：按实际 group/model 命中 user_model_ratio 后，该折扣替代分组侧倍率（含用户自定义分组、等级与全局分组倍率）；保留模型本身基础价格或表达式。0 和 1 都是有效命中，不能靠数值非零判断是否配置。
- **边界**：单独计费的搜索仍遵守自己的合同；不追溯重算已冻结任务的历史价格。未命中时使用原分组规则。
- **应提示的例子**：命中 0.8 后又乘 Tier／分组倍率，导致同一折扣重复叠加；折扣 0 被当成未配置。
- **不应提示**：模型基础价 × 命中的模型折扣；未命中时回到原分组倍率。
- **核对场景**：相同模型不同分组、命中 0／1／0.8、未命中及已冻结任务。
- **依据**：[E23](tuzi-api-evidence.md#e23)；专项文档及替代历史。

## TUZI-024

**金额到 quota 由服务端按明确单位换算。**

- **适用条件**：新增或修改金额输入、充值／管理额度换算。
- **规则**：在服务端区分金额、显示币种与原始 quota；使用当前换算配置和 decimal 路径，校验有限数、有效汇率／基数、舍入后整数范围与最小可表示量。客户端预览不能取代服务端校验。
- **边界**：保留明确的原始 quota 接口。加减操作要求正的输入幅度，但 signed 调整 helper 可接收负数；override 允许显式置零，不能统一禁止零或负数。
- **应提示的例子**：把前端显示人民币数直接当 quota 写入，或大金额转换成 int 后溢出。
- **不应提示**：使用明确 unit 的旧 quota 调用；override 明确设置余额为 0。
- **核对场景**：币种／unit 不一致、NaN／无限值、边界溢出、微小金额、负向调整与置零。
- **依据**：[E24](tuzi-api-evidence.md#e24)；明确原则及局部实现。

## TUZI-025

**管理员改额的幂等键绑定动作与载荷。**

- **适用条件**：修改 ManageUser 的 add_quota、重试或管理端提交。
- **规则**：同一逻辑提交复用管理员作用域内的幂等键；header 与 body 同时提供时一致。幂等身份包含目标账户及动作，同一身份下再核对模式和额度，重复请求不重复修改余额／审计；override 在事务内锁定当前余额后计算差额。
- **边界**：一次新操作使用新键；账户属于幂等作用域，不宣称同一字符串键在不同账户间全局唯一。禁用提交按钮不能替代数据库幂等。沿用本路径的同库／跨库审计处理，不据此声称跨库审计与余额有共同事务。
- **应提示的例子**：同一幂等键更换金额后仍执行；使用页面读取的旧余额计算 override 差额。
- **不应提示**：网络超时后带原键重试，数据库确认此前已应用并避免重复写。
- **核对场景**：并发重放、同键改载荷、header/body 冲突、余额并发变化下 override。
- **依据**：[E25](tuzi-api-evidence.md#e25)；局部历史推断。

## TUZI-026

**任务结算和退款共享互斥的终态账务依据。**

- **适用条件**：修改任务终态结算、退款、零额任务完成或账务事件重放。
- **规则**：持久化任务的结算和退款要互相检查已有终态事件，并核对计费指纹；同一终态只能生效一次，不能分别在两类事件中各自幂等却允许同时发生。零 quota 也要维护该路径的终态和计数依据。
- **边界**：不禁止有独立来源、权限和事件身份的后续管理员纠正。本条约束同一任务终态，不要求所有财务调整永久禁止。
- **应提示的例子**：退款只查退款事件，结算只查结算事件，并发时两者均成功；零额任务跳过终态登记。
- **不应提示**：已存在一致终态事件时重放返回既有结果；单独授权的修正走独立操作。
- **核对场景**：结算／退款并发、重复同类事件、指纹冲突和零额任务。
- **依据**：[E26](tuzi-api-evidence.md#e26)；局部历史推断。

## TUZI-027

**价格同步按模型版本发布，缺行不等于删除。**

- **适用条件**：修改价格同步、模型配置刷新或恢复快照。
- **规则**：按模型行的版本／摘要校验和发布，坏的单模型配置不清空其他模型价格。删除以明确 tombstone 表达；暂时未读到某行或数据库不可用时，保留已验证的 last-known-good 快照并记录异常，不凭空生成价格。
- **边界**：只允许使用经过校验的已有快照，不适用于首次价格配置的成功确认（见 TUZI-028），更不能扩大成鉴权可用旧缓存放行。
- **应提示的例子**：一轮查询缺少某模型就从运行时删除其价格；单模型 JSON 损坏使所有模型恢复为默认价。
- **不应提示**：数据库短时错误时继续使用已校验旧价，明确删除标记到达后再移除该模型。
- **核对场景**：缺行、显式删除、坏单行、重复版本、数据库不可用及正常新版本。
- **依据**：[E27](tuzi-api-evidence.md#e27)；专项设计及当前实现。

## TUZI-028

**首次价格配置区分已应用与恢复快照就绪。**

- **适用条件**：修改单模型价格保存、持久恢复状态或前端成功提示。
- **规则**：在启用共享恢复持久化的路径，首次配置及其确认重试按 durabilityRequired 核对恢复快照。尚未 durable 时保留 RecoveryPending／pricing_recovery_pending 状态，不把“运行时已发布”包装成完全就绪；调用方识别 202 与 snapshot_durable 等字段。
- **边界**：既有价格的正常更新可按现行合同成功但 snapshot_durable=false；不要求所有价格写入一律同步完成快照，也不把 202 当成数据库必定回滚。
- **应提示的例子**：首次配置恢复快照保存失败，界面只见 HTTP 2xx 就显示全部完成；随后重试又重复创建配置。
- **不应提示**：保存已生效但恢复仍待完成时返回明确 pending，并对同一配置继续确认。
- **核对场景**：首次保存、相同内容重试、既有价格更新分别模拟快照持久化失败。
- **依据**：[E28](tuzi-api-evidence.md#e28)；专项设计及当前实现。

## TUZI-029

**表达式按已计费维度拆分 token，避免重复收费。**

- **适用条件**：修改 token 分类归一化、缓存／音频计费或表达式变量语义。
- **规则**：按表达式实际使用的计费变量拆分 p/c，避免同一缓存或音频 token 同时计入普通 token 和专门价格；len 保留用于上下文分档的完整长度。遵守 provider 对 input/cache 的含义和 v2 变量使用约束。
- **边界**：没有单独使用的维度不能无条件从 p/c 扣除；v2 的 token／秒数计费互斥限制不禁止 token 变量仅用于分档条件。保留冻结表达式，不用新语义偷偷重算旧任务。
- **应提示的例子**：缓存 token 已按独立倍率收费却仍全量包含在 p 中；把用于分档的 len 同时减掉缓存长度。
- **不应提示**：只使用 p 的表达式保留其既有总输入语义；按 Claude 输入含义做对应归一化。
- **核对场景**：普通／缓存／缓存音频混合、变量仅作条件、OpenAI 与 Claude 差异。
- **依据**：[E29](tuzi-api-evidence.md#e29)；明确表达式规范及当前实现。

## TUZI-030

**找到任务运行记录不等于取得账务授权。**

- **适用条件**：修改异步任务运行态恢复、消费日志回填或据此结算／退款。
- **规则**：区分 Found、BillingReady 和经过验证的 financial authority；核对任务、公私任务 ID、上游、平台、用户、请求及日志锚点等该路径要求的身份。指定消费日志时还要精确核对 log ID 和来源，失败不能仅凭行存在继续资金操作。
- **边界**：经精确消费日志验证的候选可以被提升为账务依据；不禁止已验证的恢复路径。运营调度信息可存在而不具有资金授权。
- **应提示的例子**：Found=true 就执行退款，实际 runtime 属于另一用户或消费日志 ID 不匹配。
- **不应提示**：先恢复运行信息，再通过匹配的持久消费日志证明其可用于结算。
- **核对场景**：找到但未验证、身份冲突、精确日志不匹配、经日志验证成功四种结果。
- **依据**：[E30](tuzi-api-evidence.md#e30)；当前局部实现推断。

## TUZI-031

**用户设置以字段补丁合并并保留未知键。**

- **适用条件**：修改用户 setting JSON 的写入或添加设置字段。
- **规则**：在锁定用户行的短事务中读取最新 JSON，只覆盖此次提供的字段，保留其他已知／未知键和显式 false／0。已有 JSON 非法时明确报错，不静默覆盖成默认对象；提交后再失效相关缓存。
- **边界**：敏感字段的省略、清除按具体接口合同区分；不要求客户端回传全部设置，不把每次读取都改为加锁。
- **应提示的例子**：客户端旧设置整体保存，覆盖另一请求刚改的通知选项；解析失败直接以空 map 保存。
- **不应提示**：只提交一个字段，其他未知键及 false 原样保留。
- **核对场景**：两个不同字段并发写、未知键、false／0、SQL NULL 默认和损坏 JSON。
- **依据**：[E31](tuzi-api-evidence.md#e31)；局部历史推断。

## TUZI-032

**索引就绪校验核对有序列定义。**

- **适用条件**：修改告警／后台错误 sidecar 索引迁移或启动就绪检查。
- **规则**：迁移和只读 readiness 使用同一索引规格；校验完整有序列集合，不能仅凭同名索引存在就放行。列顺序不符、定义不完整应明确拒绝或交给受控迁移处理。
- **边界**：规格允许时同列同序的其他名字可等价；不要求所有索引都必须同名，也不能让只读启动检查顺手执行 DDL。Seedance 唯一约束的额外格式要求见 TUZI-050。
- **应提示的例子**：旧同名索引只有前两列，启动 HasIndex=true 就认为满足新查询要求。
- **不应提示**：非 exact 规格接受已有的同列同序索引，避免冗余建索引。
- **核对场景**：同名错列、错顺序、缺列、允许的异名等价和完全缺失。
- **依据**：[E32](tuzi-api-evidence.md#e32)；局部历史推断。

## TUZI-033

**字符串表名的列检查走已验证的元数据 helper。**

- **适用条件**：新增 MySQL 列存在性检查，调用方只有字符串表名。
- **规则**：复用 tableColumnExistsForDB 等现有兼容元数据入口，避免在当前 GORM/MySQL 路径直接把裸表名传入会触发 schema 解析问题的 HasColumn。元数据查询错误向上传递。
- **边界**：这是当前依赖与字符串表名调用的限制，不是禁止所有基于模型对象的 HasColumn，也不要求新增其他生产数据库兼容层。
- **应提示的例子**：迁移前直接 HasColumn("table", "column")，在当前 MySQL 驱动路径触发 panic。
- **不应提示**：使用经过验证的表列 helper；模型对象上的合法元数据调用。
- **核对场景**：表不存在、列不存在、列存在及查询失败；MySQL 验证状态按 TUZI-001 报告。
- **依据**：[E33](tuzi-api-evidence.md#e33)；明确规范及具体修复。

## TUZI-034

**日志导出逐页保留权限过滤与真实游标。**

- **适用条件**：修改消费日志 CSV 的 manifest、分页或统计。
- **规则**：每页重新应用服务端身份和相同筛选条件，使用 LOG_DB；manifest 使用准确计数并固定 ID 上下界，按真实 ID 倒序游标有界读取。展示序号替换前保存下一页游标；页读取失败不把该页当作已完成输出。
- **边界**：ID 上界只排除后分配的新 ID，不冻结已有行更新，不能宣传成 MVCC 一致快照。CSV 内容可读取所需完整 Log，不能照搬热表规范要求一律只读几个字段。
- **应提示的例子**：第二页丢失 self user_id 条件；使用展示序号作 cursor；一次拉全表导出。
- **不应提示**：每页使用同一授权查询和真实 ID，上界内已发生的合法状态更新可被读取。
- **核对场景**：普通用户／管理员、分页中新写入、展示 ID 重排、页失败重试及筛选参数变化。
- **依据**：[E34](tuzi-api-evidence.md#e34)；局部历史推断。

## TUZI-035

**后台错误分析租约用数据库时钟和领取令牌隔离。**

- **适用条件**：修改后台错误 AI 任务领取、续租、完成或投影写入。
- **规则**：用 LOG_DB 的数据库时间判断租约，领取生成独立 token；完成时核对状态、owner、token、version 和尚未过期。结果提交和投影在该数据库事务内完成，失去租约的 worker 取消工作且不能写入晚到结果。
- **边界**：ProxyID 用于观测，不当成永久任务分区。不能把 TUZI-004 中另一续租路径的“同秒零行可核验”照搬成此处任意零行成功。
- **应提示的例子**：只核对 owner，旧进程在同节点重新领取后仍提交上一次结果；依赖两节点本地时钟判断到期。
- **不应提示**：新 token 成功接管，旧 token 的提交被拒绝而结果保持新版本。
- **核对场景**：过期接管、同 owner 不同 token、版本改变、续租失败及结果与投影回滚。
- **依据**：[E35](tuzi-api-evidence.md#e35)；局部历史推断。

## TUZI-036

**后台数据库准入给在线计费留容量。**

- **适用条件**：修改共享后台扫描、供应商同步、路由质量或后台任务轮询的数据库调度。
- **规则**：复用共享准入和连接池压力判断，有压力时延后可延后扫描。准入许可在任务派发前释放，网络等待和已开始的财务收尾不能占用或等待扫描许可；混合错误里有真实失败时不能只因包含 deferred 就吞掉。
- **边界**：这是已接入协调器的后台工作合同，不等于全服务只允许一个 goroutine；用户主动刷新保留前台行为，已开始的结算不能因后台限流被遗弃。
- **应提示的例子**：拿着唯一扫描许可等上游数分钟，导致其他维护任务饿死；将资金结算也排到可无限延后的后台准入后。
- **不应提示**：数据库繁忙时暂缓下一批后台扫描，而已开始的资金操作继续完成。
- **核对场景**：连接池接近上限、准入竞争、网络等待、前台刷新及 deferred 与真实错误混合。
- **依据**：[E36](tuzi-api-evidence.md#e36)；专项设计及当前实现。

## TUZI-037

**角色与模块权限按具体操作共同约束。**

- **适用条件**：增加管理 API、拆分模块权限或调整运营员入口。
- **规则**：后端同时执行该操作要求的角色和模块权限，前端显示保持一致。用户管理列表／搜索可给有 user 权限的 Operator，但管理写入仍要求 Admin；客户端来源分析保留独立权限入口，不能强迫授予整个业务分析权限。
- **边界**：某些其他模块有意允许 Operator 写操作，不能扩大成“运营员全站只读”。本条不取代接口自己的数据归属与更高 Root 限制。
- **应提示的例子**：只隐藏改余额按钮，却让 Operator 直接调用管理写 API；读取客户端来源必须额外开整个分析模块。
- **不应提示**：有 user 权限的运营员查看列表，修改接口继续拒绝；其他模块按其明确权限允许写入。
- **核对场景**：角色×模块权限组合、直接调用 API、独立来源分析权限及 Root 专属操作。
- **依据**：[E37](tuzi-api-evidence.md#e37)；明确原则及局部修复。

## TUZI-038

**素材预览同时核对资源范围与上游绑定。**

- **适用条件**：修改 Seedance 素材内容／预览接口和代理下载。
- **规则**：先按认证身份、所有者／允许的运营权限及对应资源范围授权。需要回上游读取时，进一步核对原渠道、分组、配置指纹及上游素材标识，按受限代理路径取内容，绑定不符不得访问上游。
- **边界**：合法运营预览是已有能力，不应一律改为 owner-only。已存储内容的预览可在授权后提前返回，不要求对这条本地／存储路径强行补做供应商绑定检查。
- **应提示的例子**：知道 asset ID 即可读取别人的内容；指纹变化后仍用新渠道凭据访问旧上游素材。
- **不应提示**：合法运营员按现行权限预览；授权后的已保存内容直接读取。
- **核对场景**：匿名、其他普通用户、owner、operator，以及上游指纹变化／缺标识。
- **依据**：[E38](tuzi-api-evidence.md#e38)；局部历史推断。

## TUZI-039

**SSRF 检查约束实际拨号目标。**

- **适用条件**：修改受 SSRF 保护的 URL 拉取、DNS 解析、重定向或 DialContext。
- **规则**：按配置检查域名／端口，解析后校验候选 IP，并直接拨号已经校验的数字地址，避免校验与再次解析之间换成内网目标。重定向仍经过对应策略，不能只验证最初 URL。
- **边界**：当前策略支持明确配置的私网许可及总开关；不能把所有内部 IP 一律认定违规。规则适用于受保护的外部输入抓取，不凭名称要求全站所有连接换客户端。
- **应提示的例子**：先解析域名检查公网，再让默认 dial 再次解析同域名，DNS 切换后连接到未授权内网。
- **不应提示**：按明确许可访问内网目标；只拨号已验证的候选 IP。
- **核对场景**：DNS 多地址、校验后地址变化、私网许可、未许可地址和重定向。
- **依据**：[E39](tuzi-api-evidence.md#e39)；局部历史推断。

## TUZI-041

**H3 查询错误不冒充任务终态。**

- **适用条件**：修改 H3 查询解析、任务状态投影或历史污染修复。
- **规则**：按持久任务模型和类型选择解析器，先拒绝错误／非法响应；包装响应内外任务身份一致才采纳结果。成功需要对应结果字段；一次查询失败不能直接映射成任务失败并退款，也不能把旧污染当成功用量。
- **边界**：只对实现明确识别的历史污染形态做受限投影，不据此篡改所有旧任务或伪造 usage。正常供应商明确任务失败仍按其合同处理。
- **应提示的例子**：查询接口返回鉴权错误，解析器当作任务失败触发退款；内层结果属于另一任务却采纳 URL。
- **不应提示**：保留可重试查询错误，等待有效状态；对已识别旧污染返回限定纠正投影。
- **核对场景**：错误 envelope、内外 ID 不同、成功缺结果、有效终态与已知旧污染。
- **依据**：[E41](tuzi-api-evidence.md#e41)；局部历史推断。

## TUZI-042

**日志自动刷新每次进入默认关闭。**

- **适用条件**：修改日志自动刷新开关或共用刷新 hook。
- **规则**：每次进入页面从关闭开始，用户开启后才定时刷新；隐藏页面跳过请求，刷新进行中不再并发进入，关闭或卸载清理计时器和监听。加载器负责显示失败，共用 hook 可保持定时器存活。
- **边界**：不记住上次开关作为自动启用理由；不因有待结算日志而擅自启用。站内信等不同刷新合同见 TUZI-043，不套此默认值。
- **应提示的例子**：localStorage 恢复 enabled=true，用户重新进入时页面自己刷新；关闭后仍有定时请求。
- **不应提示**：用户开启后按既有间隔刷新当前页，页面加载器显示错误后允许下次刷新。
- **核对场景**：首次进入／重新进入、开关、隐藏页、慢请求、卸载和失败后下一轮。
- **依据**：[E42](tuzi-api-evidence.md#e42)；明确代码意图及替代历史。

## TUZI-043

**通知焦点刷新受新鲜度限制。**

- **适用条件**：调整站内信和工单未读数的 focus／visibility 刷新。
- **规则**：窗口重新聚焦或页面转为可见时，只有距上次请求超过相应轮询间隔才再次读取；保留进行中保护及卸载清理。明确的业务更新事件按自身合同及时刷新。
- **边界**：不是全局 debounce 所有刷新：首次加载、定时轮询和工单已读等事件有不同语义。不把 TUZI-042 的用户开关默认值套到消息通知。
- **应提示的例子**：每次从开发者工具点回页面都立刻请求未读数，即使上一轮刚完成。
- **不应提示**：焦点事件未到刷新间隔而跳过；明确已读事件按现有处理立即更新。
- **核对场景**：短时间多次 focus、超过间隔再聚焦、隐藏页及业务已读事件。
- **依据**：[E43](tuzi-api-evidence.md#e43)；局部历史推断。

## TUZI-044

**日志异步响应只更新仍有效的请求。**

- **适用条件**：修改日志筛选、分页、手动加载或静默刷新。
- **规则**：请求使用递增序号、取消信号和筛选快照核对有效性；新请求开始后旧响应不得覆盖列表或报旧错误，旧 finally 不能清掉新请求的 loading。静默刷新沿用当前页与筛选，并按现有约定报告失败。
- **边界**：取消请求只是减少工作，仍要校验迟到响应；用户取消不弹网络失败，但当前请求的 401 不能被当普通静默错误吞掉。
- **应提示的例子**：A 筛选慢响应晚于 B 返回，把页面改回 A；A 的 finally 让 B 提前结束 loading。
- **不应提示**：丢弃旧序号或筛选已变化的结果；当前静默请求鉴权过期仍走登录失效提示。
- **核对场景**：A/B 乱序、筛选在准备请求时变化、取消、静默失败及 401。
- **依据**：[E44](tuzi-api-evidence.md#e44)；局部历史推断。

## TUZI-045

**导出弹窗与清理事件按任务 ID 关联。**

- **适用条件**：修改跨页日志导出的弹窗、任务删除和文件分片清理。
- **规则**：关闭／删除事件核对 taskId 与当前、选中及进度中的任务身份；异步读取返回时再次核对选择。已删除／过期任务不接受晚到状态把它重新显示；清理只影响对应任务，不能把另一个正在看的导出一并清掉。
- **边界**：保存文件与关闭弹窗不等于删除任务：当前实现保留结果供继续查看统计，过期／删除另走其生命周期。无匹配任务的全局事件不当成当前弹窗命令。
- **应提示的例子**：A 的删除事件把正在查看的 B 清掉；A 已删除，迟到的存储读取却又把 A 弹窗打开。
- **不应提示**：只处理匹配 taskId 的删除事件；下载成功后保留未过期导出供再次查看统计。
- **核对场景**：A 导出完成后查看 B，再删除 A；切换任务期间迟到的存储读取。
- **依据**：[E45](tuzi-api-evidence.md#e45)；局部历史推断。

## TUZI-047
