# 企业微信审查通知

## 用户可见效果

PR 审查成功发布到 GitHub 后，由智能机器人向该仓库绑定的群直接发送：

```text
AI 审查已完成
项目：owner/repository
PR：#123 修复订单计算
查看审查结果（链接）
```

不 @成员、不要求 GitHub／企微成员关联、不使用 Message Push。普通 PR 和部分完成的 Review 都可通知；部分结果明确标注「部分检查未完成」。群消息只含完成状态、项目、PR 标题和链接，不包含 PR 描述或审查问题明细。标题以发送时 GitHub 返回值为准并打码、转义；查看 GitHub 仍需要仓库访问权限。

群开发任务的完成结果引用原需求回复；PR 审查由 GitHub 事件触发，没有对应的群原消息，因此直接发群。开发机器人自己创建的 PR 仍按既有规则跳过自动审查，不会重复通知。

## 配置与升级

1. 配置 `WECOM_BOT_ID` 和 `WECOM_BOT_SECRET`，将智能机器人加入授权群，并在群里 @它一次。企微要求会话先与机器人交互，才允许主动推送。
2. 管理页「仓库 → 群内 AI 开发」设置并启用群 ID、目标分支及开发身份。每仓库一个群，群不能重复绑定其他仓库。该群同时接收审查通知。
3. 停止旧实例，执行 `npm run migrate`，应用到 `007_bot_group_notifications.sql`，再启动新服务。启动不会自动迁移；已有数据库不重跑 baseline。
4. 不再使用旧 `WECOM_WEBHOOK_URL`。旧成员映射数据保留但不参与发送，管理页不再显示通知成员入口。升级会取消未发送的旧通道通知；旧通道中断发送保留 uncertain，不转投新群。

未配置智能机器人、仓库未绑定群或未启用绑定时，不为新 Review 建立群通知；以后启用也不扫描补发历史审查。

## 目标隔离与发送机制

发布成功时，通知在数据库中保存 Bot 通道、群 ID 与绑定版本。发送前核对仓库白名单、安装状态、仓库启用状态、群绑定及版本，并重读 PR：只有仍然 open、非 Draft、head 未变化才发送。限速等待结束、真正调用发送接口之前再次确认绑定。改绑、停用或修改设置会取消旧通知，不转投新群。

审查通知复用持有主锁的智能机器人 WebSocket，由 `aibot_send_msg` 按 `chatid` 和 `chat_type=2` 发到群。不会为发送另起连接；同一 Bot 同时只有一个有效连接。断线未认证期间不领取新的审查通知。审查通知独立轮询，开发任务运行期间仍可发送。

同一 Review 只建立一条通知。发送前写入 sending；只有企微确认成功才标记 sent。限流或系统繁忙等明确拒收最多尝试三次；超时、断线或中断发送保留 uncertain，不盲目重发。通知失败不撤销已发布的 GitHub Review，也不重新运行模型。

## 状态与排障

| 状态 | 含义 |
| --- | --- |
| pending | 等待发送或等待明确可重试错误的重试时间 |
| sending | 已进入发送步骤，尚未确认结果 |
| sent | 企业微信已确认接收；不代表客户端已读 |
| failed | 明确拒收、失权或超过重试次数 |
| uncertain | 发送结果未知，先在群里核对，不自动重发 |
| cancelled | PR、仓库或群绑定已变化，旧通知不再发送 |

日志 `wecom_notification_result` 只保存 Job、仓库、PR、状态及原因代码，不记录凭据、消息正文或上游原始错误。群绑定变化使用 `repository_or_binding_changed`，PR 变化使用 `pull_request_changed`，未知回执使用 `wecom_delivery_unknown`。可查询 `review_notifications` 与 `review_publications` 核对。

## 性能与验收

复用现有长连接，不新增 WebSocket 或前端轮询。认证成功后每 4 秒查询待发通知；有通知时通过数据库通道锁串行领取并复核，发送前读取 GitHub installation token 和 PR。群绑定复核使用仓库主键，每次投递执行三次仓库与绑定检查（领取后、GitHub 读取后、限速后）；不再读取作者映射。全机器人发送共用至少 3.1 秒间隔。没有通知时不访问 GitHub。迁移仅增加任务回复字段和通知群快照字段，并处理旧待发状态；没有线上压力测试结论。

验证需覆盖：两个仓库分别只发各自绑定群、未映射作者也能通知、无 `<@...>` 文字、改绑取消旧通知、重复发布只发送一次、断线或未知回执不重复发送。真实验收仍需要授权群客户端截图；替身回执成功不冒充真实送达。开发结果的引用与超期说明见 [开发接入说明](wecom-development.md)，完成证据见 [DEV 清单](tasks/DEV.md)。
